Vinte e um templates de apps SwiftUI para iOS 18, de e-commerce e finanças a mensagens e viagens.
Cada template é um pacote Swift independente com um app baseado em abas, dados de exemplo e testes.
Adicione um a um projeto de app no Xcode para vê-lo funcionando, ou copie-o com o seu próprio nome
usando `create-ios-app` e construa o seu app a partir dele.

Os templates são pontos de partida, não produtos prontos. Vinte deles funcionam com dados de exemplo
em memória e oferecem uma estrutura de abas funcionando, navegação e um store com testes que você
pode ligar aos seus próprios serviços. O template Clean Architecture vai um passo além: targets
Domain, Data e Presentation, uma camada HTTP com um servidor de exemplo no mesmo processo e um cache
offline.

## Destaques

- **Vinte tipos de app**: assistente de IA, reservas, vídeos curtos para criadores, CRM,
  e-commerce, educação, finanças pessoais, fitness, delivery de comida, marketplace, mensagens,
  música e podcasts, notícias, notas, cofre de privacidade, produtividade, rede social,
  assinaturas, colaboração em equipe e viagens.
- **Um app de referência em camadas**: `CleanArchitectureApp` é um diretório de equipe cujas camadas
  são targets separados, então o compilador faz cumprir a regra de dependência. Ele carrega pessoas
  por HTTP, recorre a uma cópia salva quando está offline e verifica papéis e permissões nos casos
  de uso, com 108 testes nos quatro targets e testes de UI que incluem uma auditoria de
  acessibilidade.
- **Um store com testes em cada app**: estado e ações ficam em um store `@MainActor` com uma suíte
  do Swift Testing, então as telas continuam simples e o comportamento é verificado sem interface.
- **Sem dependências de terceiros**: os templates usam apenas SwiftUI e Foundation e rodam sem
  conta, sem chave de API e sem acesso à rede.
- **O seu próprio nome**: `create-ios-app` renomeia o pacote, o módulo, os tipos, o projeto host e
  o bundle identifier, e recusa nomes que entrariam em conflito com nomes do template.
- **Claro e escuro**: todo template tem capturas de tela nas duas aparências, feitas no simulador
  por um script deste repositório.

## Início rápido

**1. Baixe os templates**

```sh
git clone https://github.com/muhittincamdali/iOSAppTemplates.git
```

**2. Adicione um template ao seu app**

No Xcode, crie um app com **File › New › Project… › iOS › App** (ou abra o seu; o deployment
target precisa ser iOS 18 ou posterior). Escolha **File › Add Package Dependencies…**, clique em
**Add Local…**, selecione a pasta `iOSAppTemplates/Templates/EcommerceApp` e clique em
**Add Package**. Adicione a biblioteca `EcommerceApp` ao target do seu app.

**3. Rode o app**

Substitua o conteúdo do arquivo que contém `@main` (em um projeto novo, o arquivo com o nome do
seu app, como `MyAppApp.swift`) por:

```swift
import EcommerceApp

@main
enum QuickStartApp {
    static func main() {
        EcommerceAppShell.main()
    }
}
```

Escolha um simulador de iPhone e pressione **Run** (⌘R). A aba Shop do template E-commerce
aparece. O projeto pronto está em [Examples/QuickStart](Examples/QuickStart).

## Instalação

### Templates

Adicione uma pasta de `Templates/` ao seu app como pacote local, como no início rápido, ou crie uma
cópia renomeada com `create-ios-app` (veja [Uso](#uso)). Os templates não são publicados como
pacotes remotos, porque cada um foi feito para ser copiado e alterado.

### create-ios-app

Rode a ferramenta a partir de um clone com `swift run create-ios-app`, ou compile-a uma vez e
execute o binário:

```sh
swift build -c release
.build/release/create-ios-app list
```

### Biblioteca TemplateScaffold

A lógica por trás do `create-ios-app` está na biblioteca `TemplateScaffold` (macOS 14 ou
posterior). Ela faz parte das versões a partir da 3.0.0:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/iOSAppTemplates.git", from: "3.0.0")
],
targets: [
    .executableTarget(name: "YourTool", dependencies: [
        .product(name: "TemplateScaffold", package: "iOSAppTemplates")
    ])
]
```

### Crie um projeto com o seu próprio nome

```bash
cd iOSAppTemplates
swift run create-ios-app list
swift run create-ios-app new MyShop --template ecommerce --output ~/Developer
```

A ferramenta copia `Templates/EcommerceApp` para `~/Developer/MyShop` e renomeia o pacote, o
módulo, o target de testes, `EcommerceAppShell`, o projeto host e o bundle identifier para usar
`MyShop`. Os nomes precisam ser identificadores Swift que comecem com uma letra ASCII. A
ferramenta não sobrescreve uma pasta existente e recusa nomes que virariam um nome que o template
já usa, como `CommerceStore` no template E-commerce.

Adicione `~/Developer/MyShop` ao seu app como no início rápido (`import MyShop`,
`MyShopShell.main()`), ou rode os testes e abra o projeto host:

```bash
cd ~/Developer/MyShop
xcodebuild test -scheme MyShop -destination 'platform=iOS Simulator,name=iPhone 17'

cd App
xcodegen generate
open MyShop.xcodeproj
```

`iPhone 17` é só um exemplo; use qualquer simulador listado por
`xcrun simctl list devices available`. O projeto host precisa do
[XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`).

### Trabalhe direto em um template

Abra `Templates/<Name>/Package.swift` no Xcode para editar o template e rodar os testes, ou gere o
projeto host em `Templates/<Name>/App` com `xcodegen generate`.

### Use a biblioteca de scaffolding

`TemplateScaffold` precisa de uma cópia local deste repositório, porque os templates são lidos de
`Templates/`:

```swift
import Foundation
import TemplateScaffold

func makeShop(templates: URL, output: URL) throws -> ScaffoldResult {
    guard let template = TemplateCatalog.template(named: "ecommerce") else {
        throw CocoaError(.fileNoSuchFile)
    }
    let name = try ProjectName("MyShop")
    return try Scaffolder(templatesDirectory: templates).scaffold(template, as: name, in: output)
}
```

A suíte de testes compila e executa este trecho.

## Arquitetura

```text
Package.swift                 create-ios-app + TemplateScaffold (macOS)
Sources/CLI/                  argument parsing (swift-argument-parser)
Sources/TemplateScaffold/     catalog, name validation, renaming, copying
Tests/TemplateScaffoldTests/  Swift Testing, including a scaffold of every template
Templates/<Name>/             21 independent iOS 18 packages with tests and an App/ host
Examples/QuickStart/          an app project that runs a template as a local package
scripts/                      test-templates.sh, capture-screenshots.sh
```

Cada template contém:

- `Sources/<Name>/`: a cena pública `<Name>Shell`, as telas e um store `@MainActor`
  `ObservableObject` que guarda os dados de exemplo e todas as ações disparadas pelas telas
  (totais do carrinho, transições de estado de pedidos e reservas, filas de aprovação etc.). A
  maioria dos templates mantém isso em `<Name>.swift`; `EcommerceApp`, `FitnessApp` e
  `SocialMediaApp` separam o store, os modelos e as telas em arquivos diferentes.
- `Tests/<Name>Tests/`: uma suíte do Swift Testing para esse store, cobrindo valores derivados,
  transições de estado, cláusulas guard para entradas inválidas e identificadores desconhecidos, e
  limites que não podem ser ultrapassados.
- `App/`: uma especificação do XcodeGen e um arquivo host que chama `<Name>Shell.main()`.

`CleanArchitectureApp` substitui o store único por quatro targets: `CleanArchitectureAppDomain`
(entidades, regras, casos de uso), `CleanArchitectureAppData` (HTTP, JSON, cache, repositório),
`CleanArchitectureAppPresentation` (modelos `@Observable` e telas) e `CleanArchitectureApp`, a raiz
de composição, cada um com o seu próprio target de testes.

Os templates não dependem do pacote raiz nem uns dos outros. A renomeação é uma substituição de
texto do nome da pasta do template; por isso todo nome que precisa mudar começa com ele
(`EcommerceApp`, `EcommerceAppShell`, `EcommerceAppTests`).

## Roteiro

- Cadastrar o pacote no Swift Package Index.
- Trocar por enums os estados ainda baseados em texto, como o título do pedido em `EcommerceApp`,
  o status de contenção em `MessagingApp` e o modo de preset em `AIAssistantApp`.
- Dividir os templates que ainda mantêm a maior parte do código em `<Name>.swift` em arquivos de
  store, modelos e telas, como `EcommerceApp`, `FitnessApp` e `SocialMediaApp` já fazem.
