二十个面向 iOS 18 的 SwiftUI 应用模板，涵盖电商、理财、即时通讯、旅行等类型。每个模板都是一个独立的 Swift 包，包含基于标签页的应用、示例数据和一个带测试的 store。你可以在 Xcode 中把模板加入应用项目直接运行，也可以用 `create-ios-app` 以自己的名称复制一份，在此基础上开发你的应用。

这些模板是起点，而不是成品：所有界面都使用内存中的示例数据，没有网络层，也没有数据库。它们提供的是可运行的标签页结构、导航，以及每个应用一个带测试的 store，你可以把它接入自己的服务。

## 亮点

- **二十种应用类型**：AI 助手、预订、创作者短视频、CRM、电商、教育、理财、健身、外卖、交易市场、即时通讯、音乐与播客、新闻、笔记、隐私保险箱、效率工具、社交媒体、订阅、团队协作和旅行。
- **每个应用一个带测试的 store**：状态和操作集中在一个 `@MainActor` store 中，并配有 Swift Testing 测试套件，因此界面保持精简，行为无需 UI 即可验证。
- **无第三方依赖**：模板只使用 SwiftUI 和 Foundation，无需账号、API 密钥或网络连接即可运行。
- **使用你自己的名称**：`create-ios-app` 会重命名包、模块、类型、宿主项目和 bundle identifier，并拒绝会与模板中已有名称冲突的名字。
- **浅色与深色**：每个模板都有两种外观的截图，由本仓库中的脚本在模拟器里截取。

## 快速开始

**1. 获取模板**

```sh
git clone https://github.com/muhittincamdali/iOSAppTemplates.git
```

**2. 把模板加入你的应用**

在 Xcode 中通过 **File › New › Project… › iOS › App** 创建一个应用（或打开你自己的应用，其 deployment target 必须为 iOS 18 或更高）。选择 **File › Add Package Dependencies…**，点击 **Add Local…**，选择 `iOSAppTemplates/Templates/EcommerceApp` 文件夹，然后点击 **Add Package**。把 `EcommerceApp` 库添加到你的应用 target。

**3. 运行**

把包含 `@main` 的文件（在新项目中就是以应用名称命名的文件，例如 `MyAppApp.swift`）的内容替换为：

```swift
import EcommerceApp

@main
enum QuickStartApp {
    static func main() {
        EcommerceAppShell.main()
    }
}
```

选择一个 iPhone 模拟器并点击 **Run**（⌘R），就会出现 E-commerce 模板的 Shop 标签页。完成后的项目位于 [Examples/QuickStart](Examples/QuickStart)。

## 安装

### 模板

像快速开始中那样，把 `Templates/` 下的某个文件夹作为本地包加入你的应用，或者用 `create-ios-app` 创建一份重命名后的副本（参见[使用方法](#使用方法)）。模板不会作为远程包发布，因为每个模板都是用来复制和修改的。

### create-ios-app

在克隆下来的仓库中用 `swift run create-ios-app` 运行该工具，或者先编译一次再运行生成的二进制文件：

```sh
swift build -c release
.build/release/create-ios-app list
```

### TemplateScaffold 库

`create-ios-app` 背后的逻辑是 `TemplateScaffold` 库（macOS 14 或更高）。它还没有包含在任何带标签的版本中（`v2.1.0` 标签是之前的结构），因此请依赖 `master` 分支：

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/iOSAppTemplates.git", branch: "master")
],
targets: [
    .executableTarget(name: "YourTool", dependencies: [
        .product(name: "TemplateScaffold", package: "iOSAppTemplates")
    ])
]
```

### 以自己的名称创建项目

```bash
cd iOSAppTemplates
swift run create-ios-app list
swift run create-ios-app new MyShop --template ecommerce --output ~/Developer
```

该工具会把 `Templates/EcommerceApp` 复制到 `~/Developer/MyShop`，并把包、模块、测试 target、 `EcommerceAppShell`、宿主项目和 bundle identifier 重命名为 `MyShop`。名称必须是以 ASCII 字母开头的 Swift 标识符。该工具不会覆盖已有目录，也会拒绝会变成模板中已有名称的名字，例如对 E-commerce 模板使用 `CommerceStore`。

像快速开始中那样把 `~/Developer/MyShop` 加入你的应用（`import MyShop`、`MyShopShell.main()`），或者运行测试并打开它的宿主项目：

```bash
cd ~/Developer/MyShop
xcodebuild test -scheme MyShop -destination 'platform=iOS Simulator,name=iPhone 17'

cd App
xcodegen generate
open MyShop.xcodeproj
```

`iPhone 17` 只是示例；可以使用 `xcrun simctl list devices available` 列出的任意模拟器。宿主项目需要 [XcodeGen](https://github.com/yonaskolb/XcodeGen)（`brew install xcodegen`）。

### 直接修改模板

在 Xcode 中打开 `Templates/<Name>/Package.swift` 即可编辑模板并运行测试，也可以在 `Templates/<Name>/App` 中用 `xcodegen generate` 生成宿主项目。

### 使用脚手架库

`TemplateScaffold` 需要本仓库的一份检出，因为模板是从 `Templates/` 读取的：

```swift
import Foundation
import TemplateScaffold

func makeShop(templates: URL, output: URL) throws -> ScaffoldResult {
    guard let template = TemplateCatalog.template(named: "ecommerce") else {
        throw CocoaError(.fileNoSuchFile)
    }
    let name = try ProjectName("MyShop")
    return try Scaffolder(templatesDirectory: templates).scaffold(template, as: name, in: output)
}
```

这段代码会由测试套件编译并运行。

## 架构

```text
Package.swift                 create-ios-app + TemplateScaffold (macOS)
Sources/CLI/                  argument parsing (swift-argument-parser)
Sources/TemplateScaffold/     catalog, name validation, renaming, copying
Tests/TemplateScaffoldTests/  Swift Testing, including a scaffold of every template
Templates/<Name>/             20 independent iOS 18 packages with tests and an App/ host
Examples/QuickStart/          an app project that runs a template as a local package
scripts/                      test-templates.sh, capture-screenshots.sh
```

每个模板包含：

- `Sources/<Name>/`：公开的 `<Name>Shell` 应用场景、各个界面，以及一个 `@MainActor` `ObservableObject` store，它持有示例数据和界面触发的所有操作（购物车总额、订单和预订的状态流转、审批队列等）。大多数模板把这些放在 `<Name>.swift` 中；`EcommerceApp`、`FitnessApp` 和 `SocialMediaApp` 则把 store、模型和界面拆分到不同文件。
- `Tests/<Name>Tests/`：针对该 store 的 Swift Testing 测试套件，覆盖派生值、状态流转、对无效输入和未知标识符的 guard 判断，以及不得超出的上限。
- `App/`：一个 XcodeGen 配置和一个调用 `<Name>Shell.main()` 的宿主文件。

模板既不依赖根包，也不相互依赖。重命名就是对模板目录名做文本替换，因此所有需要改变的名称都以它开头（`EcommerceApp`、`EcommerceAppShell`、`EcommerceAppTests`）。

## 路线图

- 把当前结构作为 3.0.0 发布并附上发布说明，同时把这个包加入 Swift Package Index。
- 用 enum 替换剩余的字符串状态，例如 `EcommerceApp` 中的订单标题、`MessagingApp` 中的 containment 状态以及 `AIAssistantApp` 中的 preset 模式。
- 像 `EcommerceApp`、`FitnessApp` 和 `SocialMediaApp` 一样，把仍将大部分代码放在 `<Name>.swift` 中的模板拆分为 store、模型和界面文件。
