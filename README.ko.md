전자상거래와 금융부터 메신저와 여행까지, iOS 18용 SwiftUI 앱 템플릿 20종입니다. 각 템플릿은 탭 기반
앱, 샘플 데이터, 테스트가 있는 store를 담은 독립적인 Swift 패키지입니다. Xcode에서 앱 프로젝트에 추가해
바로 실행해 보거나, `create-ios-app`으로 원하는 이름의 사본을 만들어 앱 개발의 출발점으로 쓸 수 있습니다.

템플릿은 완성된 제품이 아니라 출발점입니다. 모든 화면은 메모리에 있는 샘플 데이터로 동작하며 네트워크
계층이나 데이터베이스는 없습니다. 대신 동작하는 탭 구조와 내비게이션, 그리고 직접 만든 서비스에 연결할 수
있는, 테스트가 있는 store를 앱마다 제공합니다.

## 주요 기능

- **20가지 앱 유형**: AI 어시스턴트, 예약, 크리에이터 숏폼 영상, CRM, 전자상거래, 교육, 개인 금융,
  피트니스, 음식 배달, 마켓플레이스, 메신저, 음악과 팟캐스트, 뉴스, 노트, 개인정보 보관함, 생산성,
  소셜 미디어, 구독, 팀 협업, 여행.
- **앱마다 테스트가 있는 store**: 상태와 액션은 Swift Testing 테스트 스위트를 갖춘 `@MainActor` store에
  모여 있어 화면은 단순하게 유지되고, 동작은 UI 없이 검증됩니다.
- **서드파티 의존성 없음**: 템플릿은 SwiftUI와 Foundation만 사용하며 계정, API 키, 네트워크 연결 없이
  실행됩니다.
- **원하는 이름으로**: `create-ios-app`은 패키지, 모듈, 타입, 호스트 프로젝트, bundle identifier의 이름을
  바꾸고, 템플릿에 이미 있는 이름과 충돌하는 이름은 거부합니다.
- **라이트와 다크**: 모든 템플릿에 두 가지 모드의 스크린샷이 있으며, 이 저장소의 스크립트로 시뮬레이터에서
  촬영했습니다.

## 빠른 시작

**1. 템플릿 받기**

```sh
git clone https://github.com/muhittincamdali/iOSAppTemplates.git
```

**2. 앱에 템플릿 추가하기**

Xcode에서 **File › New › Project… › iOS › App**으로 앱을 만듭니다(기존 앱을 열어도 되며, deployment
target은 iOS 18 이상이어야 합니다). **File › Add Package Dependencies…**를 선택하고 **Add Local…**을
클릭한 다음 `iOSAppTemplates/Templates/EcommerceApp` 폴더를 선택하고 **Add Package**를 클릭합니다.
`EcommerceApp` 라이브러리를 앱 타깃에 추가합니다.

**3. 실행하기**

`@main`이 들어 있는 파일(새 프로젝트에서는 앱 이름으로 된 파일, 예: `MyAppApp.swift`)의 내용을 다음
코드로 바꿉니다.

```swift
import EcommerceApp

@main
enum QuickStartApp {
    static func main() {
        EcommerceAppShell.main()
    }
}
```

iPhone 시뮬레이터를 선택하고 **Run**(⌘R)을 누르면 E-commerce 템플릿의 Shop 탭이 나타납니다. 완성된
프로젝트는 [Examples/QuickStart](Examples/QuickStart)에 있습니다.

## 설치

### 템플릿

빠른 시작처럼 `Templates/` 아래의 폴더를 로컬 패키지로 앱에 추가하거나, `create-ios-app`으로 이름을 바꾼
사본을 만듭니다([사용법](#사용법) 참고). 각 템플릿은 복사해서 고쳐 쓰도록 만들어졌기 때문에 원격 패키지로는
배포하지 않습니다.

### create-ios-app

클론한 저장소에서 `swift run create-ios-app`으로 실행하거나, 한 번 빌드한 뒤 바이너리를 실행합니다.

```sh
swift build -c release
.build/release/create-ios-app list
```

### TemplateScaffold 라이브러리

`create-ios-app`의 로직은 `TemplateScaffold` 라이브러리(macOS 14 이상)에 있습니다. 3.0.0 이후
릴리스에 포함되어 있습니다.

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/iOSAppTemplates.git", from: "3.0.0")
],
targets: [
    .executableTarget(name: "YourTool", dependencies: [
        .product(name: "TemplateScaffold", package: "iOSAppTemplates")
    ])
]
```

### 원하는 이름으로 프로젝트 만들기

```bash
cd iOSAppTemplates
swift run create-ios-app list
swift run create-ios-app new MyShop --template ecommerce --output ~/Developer
```

이 도구는 `Templates/EcommerceApp`을 `~/Developer/MyShop`으로 복사하고 패키지, 모듈, 테스트 타깃,
`EcommerceAppShell`, 호스트 프로젝트, bundle identifier의 이름을 `MyShop`으로 바꿉니다. 이름은 ASCII
영문자로 시작하는 Swift 식별자여야 합니다. 이미 있는 디렉터리는 덮어쓰지 않으며, 템플릿이 이미 쓰고 있는
이름이 되는 이름(예: E-commerce 템플릿의 `CommerceStore`)도 거부합니다.

`~/Developer/MyShop`은 빠른 시작처럼 앱에 추가하거나(`import MyShop`, `MyShopShell.main()`), 테스트를
실행하고 호스트 프로젝트를 열 수 있습니다.

```bash
cd ~/Developer/MyShop
xcodebuild test -scheme MyShop -destination 'platform=iOS Simulator,name=iPhone 17'

cd App
xcodegen generate
open MyShop.xcodeproj
```

`iPhone 17`은 예시일 뿐이며, `xcrun simctl list devices available`에 나오는 어떤 시뮬레이터든 쓸 수
있습니다. 호스트 프로젝트에는 [XcodeGen](https://github.com/yonaskolb/XcodeGen)이 필요합니다
(`brew install xcodegen`).

### 템플릿을 그 자리에서 수정하기

`Templates/<Name>/Package.swift`를 Xcode에서 열면 템플릿을 수정하고 테스트를 실행할 수 있습니다.
`Templates/<Name>/App`에서 `xcodegen generate`로 호스트 프로젝트를 만들 수도 있습니다.

### 스캐폴딩 라이브러리 사용하기

템플릿을 `Templates/`에서 읽기 때문에 `TemplateScaffold`를 쓰려면 이 저장소의 체크아웃이 필요합니다.

```swift
import Foundation
import TemplateScaffold

func makeShop(templates: URL, output: URL) throws -> ScaffoldResult {
    guard let template = TemplateCatalog.template(named: "ecommerce") else {
        throw CocoaError(.fileNoSuchFile)
    }
    let name = try ProjectName("MyShop")
    return try Scaffolder(templatesDirectory: templates).scaffold(template, as: name, in: output)
}
```

이 코드는 테스트 스위트에서 컴파일되고 실행됩니다.

  빠른 시작의 자세한 설명과 그다음에 바꿀 부분.
- [How Renaming Works](Sources/TemplateScaffold/TemplateScaffold.docc/HowRenamingWorks.md):
  바뀌는 이름, 바뀌지 않는 이름, 거부되는 이름.
- [Examples](Examples): QuickStart 앱.

가이드는 영어로 되어 있습니다.

## 요구 사항

| 플랫폼                                  | 최소 버전                |
| --------------------------------------- | ------------------------ |
| iOS(템플릿)                             | 18.0                     |
| macOS(create-ios-app, TemplateScaffold) | 14.0                     |
| 툴체인                                  | Swift 6.0(tools version) |

코드는 Xcode 27.0(Swift 6.4)으로 빌드하고 테스트합니다. CI는 GitHub `macos-26` 이미지의 기본 Xcode를
사용합니다. XcodeGen은 `Templates/<Name>/App`의 호스트 프로젝트에만 필요합니다.

## 아키텍처

```text
Package.swift                 create-ios-app + TemplateScaffold (macOS)
Sources/CLI/                  argument parsing (swift-argument-parser)
Sources/TemplateScaffold/     catalog, name validation, renaming, copying
Tests/TemplateScaffoldTests/  Swift Testing, including a scaffold of every template
Templates/<Name>/             20 independent iOS 18 packages with tests and an App/ host
Examples/QuickStart/          an app project that runs a template as a local package
scripts/                      test-templates.sh, capture-screenshots.sh
```

각 템플릿의 구성:

- `Sources/<Name>/`: 공개된 `<Name>Shell` 앱 씬, 화면들, 그리고 샘플 데이터와 화면이 호출하는 모든 액션
  (장바구니 합계, 주문과 예약의 상태 전환, 승인 대기열 등)을 가진 `@MainActor` `ObservableObject` store.
  대부분의 템플릿은 이를 `<Name>.swift`에 두지만, `EcommerceApp`, `FitnessApp`, `SocialMediaApp`은
  store, 모델, 화면을 별도 파일로 나눕니다.
- `Tests/<Name>Tests/`: 그 store에 대한 Swift Testing 스위트로, 파생 값, 상태 전환, 잘못된 입력과 알 수 없는
  식별자에 대한 guard, 넘어서는 안 되는 한도를 검증합니다.
- `App/`: XcodeGen 설정과 `<Name>Shell.main()`을 호출하는 호스트 파일.

템플릿은 루트 패키지에도, 서로에게도 의존하지 않습니다. 이름 변경은 템플릿 디렉터리 이름의 텍스트 치환이므로
바뀌어야 하는 이름은 모두 그 이름으로 시작합니다(`EcommerceApp`, `EcommerceAppShell`,
`EcommerceAppTests`).

## 로드맵

- 패키지를 Swift Package Index에 등록합니다.
- 남아 있는 문자열 기반 상태를 enum으로 바꿉니다. 예를 들어 `EcommerceApp`의 주문 헤드라인,
  `MessagingApp`의 containment 상태, `AIAssistantApp`의 preset 모드입니다.
- 아직 코드 대부분을 `<Name>.swift`에 두고 있는 템플릿을 `EcommerceApp`, `FitnessApp`, `SocialMediaApp`처럼
  store, 모델, 화면 파일로 나눕니다.
