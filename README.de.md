Einundzwanzig SwiftUI-App-Vorlagen für iOS 18, von E-Commerce und Finanzen bis zu Messaging und
Reisen. Jede Vorlage ist ein eigenständiges Swift-Paket mit einer tabbasierten App, Beispieldaten
und Tests. Füge eine Vorlage in Xcode zu einem App-Projekt hinzu, um sie laufen zu sehen, oder
kopiere sie mit `create-ios-app` unter deinem eigenen Namen und baue deine App darauf auf.

Die Vorlagen sind Ausgangspunkte, keine fertigen Produkte. Zwanzig davon arbeiten mit Beispieldaten
im Speicher und geben dir eine funktionierende Tab-Struktur, Navigation und einen getesteten Store,
den du an deine eigenen Dienste anbinden kannst. Die Clean-Architecture-Vorlage geht einen Schritt
weiter: Targets für Domain, Data und Presentation, eine HTTP-Schicht mit einem Beispielserver im
selben Prozess und ein Offline-Cache.

## Highlights

- **Zwanzig App-Typen**: KI-Assistent, Buchungen, Kurzvideos für Creator, CRM, E-Commerce, Bildung,
  persönliche Finanzen, Fitness, Essenslieferung, Marktplatz, Messaging, Musik und Podcasts,
  Nachrichten, Notizen, Privacy-Tresor, Produktivität, Social Media, Abonnements,
  Teamzusammenarbeit und Reisen.
- **Eine geschichtete Referenz-App**: `CleanArchitectureApp` ist ein Team-Verzeichnis, dessen
  Schichten getrennte Targets sind, sodass der Compiler die Abhängigkeitsregel durchsetzt. Die App
  lädt Personen per HTTP, greift offline auf eine gespeicherte Kopie zurück und prüft Rollen und
  Berechtigungen in Use Cases; dazu kommen 108 Tests in den vier Targets sowie UI-Tests mit einem
  Accessibility-Audit.
- **Ein getesteter Store pro App**: Zustand und Aktionen liegen in einem `@MainActor`-Store mit
  einer Swift-Testing-Suite. Die Screens bleiben schlank, und das Verhalten wird ohne UI geprüft.
- **Keine Abhängigkeiten von Drittanbietern**: Die Vorlagen nutzen nur SwiftUI und Foundation und
  laufen ohne Konto, API-Schlüssel oder Netzwerkzugriff.
- **Dein eigener Name**: `create-ios-app` benennt Paket, Modul, Typen, Host-Projekt und Bundle
  Identifier um und lehnt Namen ab, die mit Namen in der Vorlage kollidieren würden.
- **Hell und dunkel**: Für jede Vorlage gibt es Screenshots in beiden Darstellungen, aufgenommen im
  Simulator mit einem Skript aus diesem Repository.

## Schnellstart

**1. Vorlagen herunterladen**

```sh
git clone https://github.com/muhittincamdali/iOSAppTemplates.git
```

**2. Eine Vorlage zur App hinzufügen**

Erstelle in Xcode eine App mit **File › New › Project… › iOS › App** (oder öffne deine eigene App;
ihr Deployment Target muss iOS 18 oder neuer sein). Wähle **File › Add Package Dependencies…**,
klicke auf **Add Local…**, wähle den Ordner `iOSAppTemplates/Templates/EcommerceApp` und klicke auf
**Add Package**. Füge die Bibliothek `EcommerceApp` deinem App-Target hinzu.

**3. Starten**

Ersetze den Inhalt der Datei mit `@main` (in einem neuen Projekt die Datei mit dem Namen deiner
App, etwa `MyAppApp.swift`) durch:

```swift
import EcommerceApp

@main
enum QuickStartApp {
    static func main() {
        EcommerceAppShell.main()
    }
}
```

Wähle einen iPhone-Simulator und drücke **Run** (⌘R). Der Shop-Tab der E-Commerce-Vorlage
erscheint. Das fertige Projekt liegt in [Examples/QuickStart](Examples/QuickStart).

## Installation

### Vorlagen

Füge einen Ordner aus `Templates/` wie im Schnellstart als lokales Paket zu deiner App hinzu, oder
erstelle mit `create-ios-app` eine umbenannte Kopie (siehe [Verwendung](#verwendung)). Die Vorlagen
werden nicht als Remote-Pakete veröffentlicht, weil jede dazu gedacht ist, kopiert und verändert zu
werden.

### create-ios-app

Starte das Tool in einem Klon mit `swift run create-ios-app`, oder baue es einmal und führe die
Binärdatei aus:

```sh
swift build -c release
.build/release/create-ios-app list
```

### Bibliothek TemplateScaffold

Die Logik hinter `create-ios-app` steckt in der Bibliothek `TemplateScaffold` (macOS 14 oder
neuer). Sie ist ab Version 3.0.0 in den Releases enthalten:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/iOSAppTemplates.git", from: "3.0.0")
],
targets: [
    .executableTarget(name: "YourTool", dependencies: [
        .product(name: "TemplateScaffold", package: "iOSAppTemplates")
    ])
]
```

### Ein Projekt unter eigenem Namen erstellen

```bash
cd iOSAppTemplates
swift run create-ios-app list
swift run create-ios-app new MyShop --template ecommerce --output ~/Developer
```

Das Tool kopiert `Templates/EcommerceApp` nach `~/Developer/MyShop` und benennt Paket, Modul,
Test-Target, `EcommerceAppShell`, Host-Projekt und Bundle Identifier in `MyShop` um. Namen müssen
Swift-Bezeichner sein, die mit einem ASCII-Buchstaben beginnen. Das Tool überschreibt kein
vorhandenes Verzeichnis und lehnt Namen ab, aus denen ein Name würde, den die Vorlage schon
verwendet, etwa `CommerceStore` bei der E-Commerce-Vorlage.

Füge `~/Developer/MyShop` wie im Schnellstart zu deiner App hinzu (`import MyShop`,
`MyShopShell.main()`), oder führe die Tests aus und öffne das Host-Projekt:

```bash
cd ~/Developer/MyShop
xcodebuild test -scheme MyShop -destination 'platform=iOS Simulator,name=iPhone 17'

cd App
xcodegen generate
open MyShop.xcodeproj
```

`iPhone 17` ist nur ein Beispiel; du kannst jeden Simulator verwenden, den
`xcrun simctl list devices available` auflistet. Für das Host-Projekt brauchst du
[XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`).

### Direkt an einer Vorlage arbeiten

Öffne `Templates/<Name>/Package.swift` in Xcode, um die Vorlage zu bearbeiten und ihre Tests
auszuführen, oder erzeuge ihr Host-Projekt in `Templates/<Name>/App` mit `xcodegen generate`.

### Die Scaffolding-Bibliothek verwenden

`TemplateScaffold` braucht einen Checkout dieses Repositorys, weil die Vorlagen aus `Templates/`
gelesen werden:

```swift
import Foundation
import TemplateScaffold

func makeShop(templates: URL, output: URL) throws -> ScaffoldResult {
    guard let template = TemplateCatalog.template(named: "ecommerce") else {
        throw CocoaError(.fileNoSuchFile)
    }
    let name = try ProjectName("MyShop")
    return try Scaffolder(templatesDirectory: templates).scaffold(template, as: name, in: output)
}
```

Die Test-Suite kompiliert diesen Code und führt ihn aus.

## Architektur

```text
Package.swift                 create-ios-app + TemplateScaffold (macOS)
Sources/CLI/                  argument parsing (swift-argument-parser)
Sources/TemplateScaffold/     catalog, name validation, renaming, copying
Tests/TemplateScaffoldTests/  Swift Testing, including a scaffold of every template
Templates/<Name>/             21 independent iOS 18 packages with tests and an App/ host
Examples/QuickStart/          an app project that runs a template as a local package
scripts/                      test-templates.sh, capture-screenshots.sh
```

Jede Vorlage enthält:

- `Sources/<Name>/`: die öffentliche App-Szene `<Name>Shell`, die Screens und einen `@MainActor`
  `ObservableObject`-Store, dem die Beispieldaten und alle Aktionen der Screens gehören
  (Warenkorbsummen, Statusübergänge von Bestellungen und Buchungen, Freigabe-Warteschlangen und so
  weiter). Die meisten Vorlagen halten das in `<Name>.swift`; `EcommerceApp`, `FitnessApp` und
  `SocialMediaApp` teilen Store, Modelle und Screens auf eigene Dateien auf.
- `Tests/<Name>Tests/`: eine Swift-Testing-Suite für diesen Store mit abgeleiteten Werten,
  Statusübergängen, Guard-Bedingungen für ungültige Eingaben und unbekannte Bezeichner sowie
  Grenzen, die nicht überschritten werden dürfen.
- `App/`: eine XcodeGen-Spezifikation und eine Host-Datei, die `<Name>Shell.main()` aufruft.

`CleanArchitectureApp` ersetzt den einzelnen Store durch vier Targets: `CleanArchitectureAppDomain`
(Entitäten, Regeln, Use Cases), `CleanArchitectureAppData` (HTTP, JSON, Cache, Repository),
`CleanArchitectureAppPresentation` (`@Observable`-Modelle und Screens) und `CleanArchitectureApp`,
die Composition Root; jedes hat ein eigenes Test-Target.

Die Vorlagen hängen weder vom Root-Paket noch voneinander ab. Das Umbenennen ist eine
Textersetzung des Verzeichnisnamens der Vorlage; deshalb beginnt jeder Name, der sich ändern muss,
damit (`EcommerceApp`, `EcommerceAppShell`, `EcommerceAppTests`).

## Roadmap

- Das Paket im Swift Package Index eintragen.
- Die übrigen Zustände auf Textbasis durch Enums ersetzen, etwa die Bestellüberschrift in
  `EcommerceApp`, den Containment-Status in `MessagingApp` und den Preset-Modus in
  `AIAssistantApp`.
- Die Vorlagen, die noch den Großteil ihres Codes in `<Name>.swift` haben, in Store-, Modell- und
  Screen-Dateien aufteilen, wie es `EcommerceApp`, `FitnessApp` und `SocialMediaApp` bereits tun.
