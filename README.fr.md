Vingt et un modèles d'apps SwiftUI pour iOS 18, du e-commerce et de la finance à la messagerie et au
voyage. Chaque modèle est un package Swift indépendant avec une app à onglets, des données d'exemple
et des tests. Ajoutez-en un à un projet d'app dans Xcode pour le voir tourner, ou copiez-le sous
votre propre nom avec `create-ios-app` et construisez votre app à partir de là.

Ces modèles sont des points de départ, pas des produits finis. Vingt d'entre eux fonctionnent avec
des données d'exemple en mémoire et vous donnent une structure d'onglets qui fonctionne, la
navigation et un store testé que vous pouvez brancher sur vos propres services. Le modèle Clean
Architecture va un cran plus loin : des targets Domain, Data et Presentation, une couche HTTP avec
un serveur d'exemple dans le même processus, et un cache hors ligne.

## Points forts

- **Vingt types d'apps** : assistant IA, réservations, vidéo courte pour créateurs, CRM,
  e-commerce, éducation, finances personnelles, fitness, livraison de repas, marketplace,
  messagerie, musique et podcasts, actualités, notes, coffre-fort de confidentialité, productivité,
  réseau social, abonnements, collaboration d'équipe et voyage.
- **Une app de référence en couches** : `CleanArchitectureApp` est un annuaire d'équipe dont les
  couches sont des targets distincts, si bien que le compilateur impose la règle de dépendance. Elle
  charge les personnes via HTTP, se rabat sur une copie enregistrée hors ligne et vérifie les rôles
  et les permissions dans des cas d'usage, avec 108 tests répartis sur les quatre targets et des
  tests d'UI qui incluent un audit d'accessibilité.
- **Un store testé par app** : l'état et les actions sont regroupés dans un store `@MainActor`
  doté d'une suite Swift Testing ; les écrans restent simples et le comportement est vérifié sans
  interface.
- **Aucune dépendance tierce** : les modèles n'utilisent que SwiftUI et Foundation, et
  fonctionnent sans compte, sans clé d'API et sans accès réseau.
- **Votre propre nom** : `create-ios-app` renomme le package, le module, les types, le projet hôte
  et le bundle identifier, et refuse les noms qui entreraient en conflit avec des noms du modèle.
- **Clair et sombre** : chaque modèle a des captures d'écran dans les deux apparences, prises dans
  le simulateur par un script de ce dépôt.

## Démarrage rapide

**1. Récupérez les modèles**

```sh
git clone https://github.com/muhittincamdali/iOSAppTemplates.git
```

**2. Ajoutez un modèle à votre app**

Dans Xcode, créez une app avec **File › New › Project… › iOS › App** (ou ouvrez la vôtre ; sa
deployment target doit être iOS 18 ou ultérieur). Choisissez **File › Add Package Dependencies…**,
cliquez sur **Add Local…**, sélectionnez le dossier `iOSAppTemplates/Templates/EcommerceApp` puis
cliquez sur **Add Package**. Ajoutez la bibliothèque `EcommerceApp` à la cible de votre app.

**3. Lancez-la**

Remplacez le contenu du fichier qui contient `@main` (dans un nouveau projet, celui qui porte le
nom de votre app, par exemple `MyAppApp.swift`) par :

```swift
import EcommerceApp

@main
enum QuickStartApp {
    static func main() {
        EcommerceAppShell.main()
    }
}
```

Choisissez un simulateur d'iPhone et appuyez sur **Run** (⌘R). L'onglet Shop du modèle E-commerce
s'affiche. Le projet terminé se trouve dans [Examples/QuickStart](Examples/QuickStart).

## Installation

### Modèles

Ajoutez un dossier de `Templates/` à votre app comme package local, comme dans le démarrage
rapide, ou créez une copie renommée avec `create-ios-app` (voir [Utilisation](#utilisation)). Les
modèles ne sont pas publiés comme packages distants, car chacun est fait pour être copié et
modifié.

### create-ios-app

Lancez l'outil depuis un clone avec `swift run create-ios-app`, ou compilez-le une fois et exécutez
le binaire :

```sh
swift build -c release
.build/release/create-ios-app list
```

### Bibliothèque TemplateScaffold

La logique de `create-ios-app` se trouve dans la bibliothèque `TemplateScaffold` (macOS 14 ou
ultérieur). Elle fait partie des versions à partir de la 3.0.0 :

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/iOSAppTemplates.git", from: "3.0.0")
],
targets: [
    .executableTarget(name: "YourTool", dependencies: [
        .product(name: "TemplateScaffold", package: "iOSAppTemplates")
    ])
]
```

### Créer un projet sous votre propre nom

```bash
cd iOSAppTemplates
swift run create-ios-app list
swift run create-ios-app new MyShop --template ecommerce --output ~/Developer
```

L'outil copie `Templates/EcommerceApp` dans `~/Developer/MyShop` et renomme le package, le module,
la cible de tests, `EcommerceAppShell`, le projet hôte et le bundle identifier pour utiliser
`MyShop`. Les noms doivent être des identifiants Swift commençant par une lettre ASCII. L'outil
n'écrase jamais un dossier existant et refuse les noms qui deviendraient un nom déjà utilisé par le
modèle, comme `CommerceStore` pour le modèle E-commerce.

Ajoutez `~/Developer/MyShop` à votre app comme dans le démarrage rapide (`import MyShop`,
`MyShopShell.main()`), ou lancez ses tests et ouvrez son projet hôte :

```bash
cd ~/Developer/MyShop
xcodebuild test -scheme MyShop -destination 'platform=iOS Simulator,name=iPhone 17'

cd App
xcodegen generate
open MyShop.xcodeproj
```

`iPhone 17` n'est qu'un exemple ; utilisez n'importe quel simulateur listé par
`xcrun simctl list devices available`. Le projet hôte nécessite
[XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`).

### Travailler directement sur un modèle

Ouvrez `Templates/<Name>/Package.swift` dans Xcode pour modifier le modèle et lancer ses tests, ou
générez son projet hôte depuis `Templates/<Name>/App` avec `xcodegen generate`.

### Utiliser la bibliothèque de scaffolding

`TemplateScaffold` a besoin d'une copie locale de ce dépôt, car les modèles sont lus dans
`Templates/` :

```swift
import Foundation
import TemplateScaffold

func makeShop(templates: URL, output: URL) throws -> ScaffoldResult {
    guard let template = TemplateCatalog.template(named: "ecommerce") else {
        throw CocoaError(.fileNoSuchFile)
    }
    let name = try ProjectName("MyShop")
    return try Scaffolder(templatesDirectory: templates).scaffold(template, as: name, in: output)
}
```

La suite de tests compile et exécute cet extrait.

## Architecture

```text
Package.swift                 create-ios-app + TemplateScaffold (macOS)
Sources/CLI/                  argument parsing (swift-argument-parser)
Sources/TemplateScaffold/     catalog, name validation, renaming, copying
Tests/TemplateScaffoldTests/  Swift Testing, including a scaffold of every template
Templates/<Name>/             21 independent iOS 18 packages with tests and an App/ host
Examples/QuickStart/          an app project that runs a template as a local package
scripts/                      test-templates.sh, capture-screenshots.sh
```

Chaque modèle contient :

- `Sources/<Name>/` : la scène d'app publique `<Name>Shell`, les écrans et un store `@MainActor`
  `ObservableObject` qui possède les données d'exemple et toutes les actions déclenchées par les
  écrans (totaux du panier, transitions d'état des commandes et des réservations, files
  d'approbation, etc.). La plupart des modèles gardent tout cela dans `<Name>.swift` ;
  `EcommerceApp`, `FitnessApp` et `SocialMediaApp` répartissent le store, les modèles de données
  et les écrans dans des fichiers séparés.
- `Tests/<Name>Tests/` : une suite Swift Testing pour ce store, qui couvre les valeurs dérivées,
  les transitions d'état, les clauses guard pour les entrées invalides et les identifiants
  inconnus, ainsi que les limites à ne pas dépasser.
- `App/` : une spécification XcodeGen et un fichier hôte qui appelle `<Name>Shell.main()`.

`CleanArchitectureApp` remplace le store unique par quatre targets : `CleanArchitectureAppDomain`
(entités, règles, cas d'usage), `CleanArchitectureAppData` (HTTP, JSON, cache, repository),
`CleanArchitectureAppPresentation` (modèles `@Observable` et écrans) et `CleanArchitectureApp`, la
racine de composition, chacun avec son propre target de tests.

Les modèles ne dépendent ni du package racine ni les uns des autres. Le renommage est une
substitution de texte du nom de dossier du modèle ; c'est pourquoi chaque nom qui doit changer
commence par lui (`EcommerceApp`, `EcommerceAppShell`, `EcommerceAppTests`).

## Feuille de route

- Inscrire le package au Swift Package Index.
- Remplacer par des enums les états encore représentés par du texte, comme le titre de commande
  dans `EcommerceApp`, l'état de confinement dans `MessagingApp` et le mode de preset dans
  `AIAssistantApp`.
- Découper les modèles qui gardent encore l'essentiel de leur code dans `<Name>.swift` en fichiers
  de store, de modèles de données et d'écrans, comme le font déjà `EcommerceApp`, `FitnessApp` et
  `SocialMediaApp`.
