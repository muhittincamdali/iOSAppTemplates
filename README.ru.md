Двадцать шаблонов SwiftUI-приложений для iOS 18: от интернет-магазина и финансов до мессенджера и
путешествий. Каждый шаблон — отдельный Swift-пакет с приложением на вкладках, демонстрационными
данными и store с тестами. Добавьте шаблон в проект приложения в Xcode, чтобы увидеть его в работе,
или скопируйте его под своим именем с помощью `create-ios-app` и стройте на нём своё приложение.

Шаблоны — это отправная точка, а не готовый продукт: все экраны работают на демонстрационных
данных в памяти, сетевого слоя и базы данных нет. Зато у вас есть работающая структура вкладок,
навигация и для каждого приложения store с тестами, который можно подключить к своим сервисам.

## Основные возможности

- **Двадцать типов приложений**: ИИ-ассистент, бронирование, короткие видео для авторов, CRM,
  интернет-магазин, обучение, личные финансы, фитнес, доставка еды, маркетплейс, мессенджер, музыка
  и подкасты, новости, заметки, приватное хранилище, продуктивность, соцсеть, подписки, командная
  работа и путешествия.
- **Store с тестами в каждом приложении**: состояние и действия собраны в `@MainActor` store с
  набором тестов Swift Testing, поэтому экраны остаются простыми, а поведение проверяется без UI.
- **Без сторонних зависимостей**: шаблоны используют только SwiftUI и Foundation и работают без
  аккаунта, API-ключа и доступа к сети.
- **Ваше собственное имя**: `create-ios-app` переименовывает пакет, модуль, типы, host-проект и
  bundle identifier и отклоняет имена, которые совпали бы с уже существующими именами в шаблоне.
- **Светлая и тёмная темы**: для каждого шаблона есть скриншоты в обоих оформлениях; их снимает в
  симуляторе скрипт из этого репозитория.

## Быстрый старт

**1. Скачайте шаблоны**

```sh
git clone https://github.com/muhittincamdali/iOSAppTemplates.git
```

**2. Добавьте шаблон в приложение**

В Xcode создайте приложение через **File › New › Project… › iOS › App** (или откройте своё;
deployment target должен быть iOS 18 или новее). Выберите **File › Add Package Dependencies…**,
нажмите **Add Local…**, выберите папку `iOSAppTemplates/Templates/EcommerceApp` и нажмите
**Add Package**. Добавьте библиотеку `EcommerceApp` в target приложения.

**3. Запустите**

Замените содержимое файла с `@main` (в новом проекте это файл с именем приложения, например
`MyAppApp.swift`) на:

```swift
import EcommerceApp

@main
enum QuickStartApp {
    static func main() {
        EcommerceAppShell.main()
    }
}
```

Выберите симулятор iPhone и нажмите **Run** (⌘R). Откроется вкладка Shop шаблона E-commerce.
Готовый проект лежит в [Examples/QuickStart](Examples/QuickStart).

## Установка

### Шаблоны

Добавьте папку из `Templates/` в приложение как локальный пакет, как в быстром старте, или создайте
переименованную копию с помощью `create-ios-app` (см. [Использование](#использование)). Шаблоны не
публикуются как удалённые пакеты: каждый из них предназначен для того, чтобы его скопировали и
изменили.

### create-ios-app

Запускайте утилиту из клона командой `swift run create-ios-app` или соберите её один раз и
запускайте бинарный файл:

```sh
swift build -c release
.build/release/create-ios-app list
```

### Библиотека TemplateScaffold

Логика `create-ios-app` находится в библиотеке `TemplateScaffold` (macOS 14 или новее). Она ещё не
вошла ни в один релиз с тегом (тег `v2.1.0` содержит прежнюю структуру), поэтому подключайте ветку
`master`:

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/iOSAppTemplates.git", branch: "master")
],
targets: [
    .executableTarget(name: "YourTool", dependencies: [
        .product(name: "TemplateScaffold", package: "iOSAppTemplates")
    ])
]
```

### Создайте проект под своим именем

```bash
cd iOSAppTemplates
swift run create-ios-app list
swift run create-ios-app new MyShop --template ecommerce --output ~/Developer
```

Утилита копирует `Templates/EcommerceApp` в `~/Developer/MyShop` и переименовывает пакет, модуль,
тестовый target, `EcommerceAppShell`, host-проект и bundle identifier в `MyShop`. Имя должно быть
идентификатором Swift, начинающимся с латинской буквы ASCII. Утилита не перезаписывает
существующую папку и отклоняет имена, которые превратились бы в имя, уже занятое в шаблоне,
например `CommerceStore` для шаблона E-commerce.

Добавьте `~/Developer/MyShop` в приложение, как в быстром старте (`import MyShop`,
`MyShopShell.main()`), или запустите тесты и откройте host-проект:

```bash
cd ~/Developer/MyShop
xcodebuild test -scheme MyShop -destination 'platform=iOS Simulator,name=iPhone 17'

cd App
xcodegen generate
open MyShop.xcodeproj
```

`iPhone 17` — лишь пример; подойдёт любой симулятор из списка
`xcrun simctl list devices available`. Для host-проекта нужен
[XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`).

### Работайте с шаблоном на месте

Откройте `Templates/<Name>/Package.swift` в Xcode, чтобы править шаблон и запускать его тесты, или
сгенерируйте host-проект в `Templates/<Name>/App` командой `xcodegen generate`.

### Используйте библиотеку для создания проектов

`TemplateScaffold` нужна локальная копия этого репозитория, потому что шаблоны читаются из
`Templates/`:

```swift
import Foundation
import TemplateScaffold

func makeShop(templates: URL, output: URL) throws -> ScaffoldResult {
    guard let template = TemplateCatalog.template(named: "ecommerce") else {
        throw CocoaError(.fileNoSuchFile)
    }
    let name = try ProjectName("MyShop")
    return try Scaffolder(templatesDirectory: templates).scaffold(template, as: name, in: output)
}
```

Этот фрагмент компилируется и выполняется набором тестов.

## Требования

| Платформа                                | Минимальная версия        |
| ---------------------------------------- | ------------------------- |
| iOS (шаблоны)                            | 18.0                      |
| macOS (create-ios-app, TemplateScaffold) | 14.0                      |
| Инструменты                              | Swift 6.0 (tools version) |

Код собирается и тестируется в Xcode 27.0 (Swift 6.4); CI использует Xcode по умолчанию из образа
GitHub `macos-26`. XcodeGen нужен только для host-проектов в `Templates/<Name>/App`.

## Архитектура

```text
Package.swift                 create-ios-app + TemplateScaffold (macOS)
Sources/CLI/                  argument parsing (swift-argument-parser)
Sources/TemplateScaffold/     catalog, name validation, renaming, copying
Tests/TemplateScaffoldTests/  Swift Testing, including a scaffold of every template
Templates/<Name>/             20 independent iOS 18 packages with tests and an App/ host
Examples/QuickStart/          an app project that runs a template as a local package
scripts/                      test-templates.sh, capture-screenshots.sh
```

Каждый шаблон содержит:

- `Sources/<Name>/`: публичную сцену приложения `<Name>Shell`, экраны и `@MainActor`
  `ObservableObject` store, которому принадлежат демонстрационные данные и все действия экранов
  (суммы корзины, смена статусов заказов и бронирований, очереди согласования и так далее).
  Большинство шаблонов держат это в `<Name>.swift`; `EcommerceApp`, `FitnessApp` и
  `SocialMediaApp` разносят store, модели и экраны по отдельным файлам.
- `Tests/<Name>Tests/`: набор тестов Swift Testing для этого store: производные значения, смена
  состояний, guard-условия для некорректного ввода и неизвестных идентификаторов, а также пределы,
  которые нельзя превышать.
- `App/`: спецификацию XcodeGen и host-файл, который вызывает `<Name>Shell.main()`.

Шаблоны не зависят ни от корневого пакета, ни друг от друга. Переименование — это текстовая
замена имени папки шаблона, поэтому каждое имя, которое должно измениться, начинается с него
(`EcommerceApp`, `EcommerceAppShell`, `EcommerceAppTests`).

## План развития

- Выпустить текущую структуру как 3.0.0 с примечаниями к выпуску и добавить пакет в Swift Package
  Index.
- Заменить на enum оставшиеся строковые состояния, например заголовок заказа в `EcommerceApp`,
  статус изоляции в `MessagingApp` и режим пресета в `AIAssistantApp`.
- Разделить шаблоны, в которых большая часть кода всё ещё лежит в `<Name>.swift`, на файлы store,
  моделей и экранов, как уже сделано в `EcommerceApp`, `FitnessApp` и `SocialMediaApp`.
