EC、家計管理、メッセージング、旅行など、iOS 18 向けの SwiftUI アプリテンプレートが 21 種類あります。各テンプレートは独立した Swift パッケージで、タブ構成のアプリ、サンプルデータ、テストを含みます。Xcode でアプリプロジェクトに追加してそのまま動かすことも、`create-ios-app` で自分の名前に複製してアプリ開発の土台にすることもできます。

テンプレートは完成品ではなく出発点です。そのうち 20 種類はメモリ上のサンプルデータで動作し、動作するタブ構成とナビゲーション、自分のサービスにつなぎ込めるテスト付きの store を提供します。Clean Architecture テンプレートはさらに一歩進み、Domain・Data・Presentation の各ターゲット、プロセス内のサンプルサーバーを使う HTTP 層、オフラインキャッシュを備えています。

## 主な特長

- **20 種類のアプリ**：AI アシスタント、予約、クリエイター向けショート動画、CRM、EC、教育、家計管理、フィットネス、フードデリバリー、マーケットプレイス、メッセージング、音楽とポッドキャスト、ニュース、ノート、プライバシー保管庫、生産性、SNS、サブスクリプション、チームコラボレーション、旅行。
- **レイヤー構成のリファレンスアプリ**：`CleanArchitectureApp` はチームのディレクトリアプリで、各レイヤーが別々のターゲットなので、依存関係のルールはコンパイラが強制します。人物一覧を HTTP で読み込み、オフライン時は保存済みのコピーに切り替え、ロールと権限を use case で検証します。4 つのターゲットに 108 件のテストがあり、アクセシビリティ監査を含む UI テストもあります。
- **アプリごとにテスト付きの store**：状態とアクションは Swift Testing のテストスイートを持つ `@MainActor` の store にまとまっているため、画面はシンプルなまま、振る舞いを UI なしで検証できます。
- **サードパーティ依存なし**：テンプレートは SwiftUI と Foundation だけを使い、アカウントや API キー、ネットワーク接続なしで動作します。
- **自分の名前で**：`create-ios-app` はパッケージ、モジュール、型、ホストプロジェクト、bundle identifier の名前を変更し、テンプレート内の既存の名前と衝突する名前は受け付けません。
- **ライトとダーク**：すべてのテンプレートに両方の外観のスクリーンショットがあり、このリポジトリのスクリプトでシミュレータから撮影しています。

## クイックスタート

**1. テンプレートを取得する**

```sh
git clone https://github.com/muhittincamdali/iOSAppTemplates.git
```

**2. アプリにテンプレートを追加する**

Xcode で **File › New › Project… › iOS › App** からアプリを作成します（既存のアプリを開いても構いません。deployment target は iOS 18 以上にしてください）。**File › Add Package Dependencies…** を選び、**Add Local…** をクリックして `iOSAppTemplates/Templates/EcommerceApp` フォルダを選択し、 **Add Package** をクリックします。`EcommerceApp` ライブラリをアプリのターゲットに追加します。

**3. 起動する**

`@main` を含むファイル（新規プロジェクトではアプリ名のファイル、たとえば `MyAppApp.swift`）の内容を次のコードに置き換えます。

```swift
import EcommerceApp

@main
enum QuickStartApp {
    static func main() {
        EcommerceAppShell.main()
    }
}
```

iPhone シミュレータを選んで **Run**（⌘R）を押すと、E-commerce テンプレートの Shop タブが表示されます。完成したプロジェクトは [Examples/QuickStart](Examples/QuickStart) にあります。

## インストール

### テンプレート

クイックスタートと同じように `Templates/` 内のフォルダをローカルパッケージとしてアプリに追加するか、 `create-ios-app` で名前を変えたコピーを作成します（[使い方](#使い方)を参照）。テンプレートは複製して書き換える前提のため、リモートパッケージとしては公開していません。

### create-ios-app

クローンしたリポジトリで `swift run create-ios-app` を実行するか、一度ビルドしてバイナリを実行します。

```sh
swift build -c release
.build/release/create-ios-app list
```

### TemplateScaffold ライブラリ

`create-ios-app` のロジックは `TemplateScaffold` ライブラリ（macOS 14 以上）にあります。3.0.0 以降のリリースに含まれています。

```swift
dependencies: [
    .package(url: "https://github.com/muhittincamdali/iOSAppTemplates.git", from: "3.0.0")
],
targets: [
    .executableTarget(name: "YourTool", dependencies: [
        .product(name: "TemplateScaffold", package: "iOSAppTemplates")
    ])
]
```

### 自分の名前でプロジェクトを作成する

```bash
cd iOSAppTemplates
swift run create-ios-app list
swift run create-ios-app new MyShop --template ecommerce --output ~/Developer
```

このツールは `Templates/EcommerceApp` を `~/Developer/MyShop` にコピーし、パッケージ、モジュール、テストターゲット、`EcommerceAppShell`、ホストプロジェクト、bundle identifier の名前を `MyShop` に変更します。名前は ASCII 英字で始まる Swift の識別子でなければなりません。既存のディレクトリは上書きせず、テンプレートですでに使われている名前になってしまう名前（E-commerce テンプレートに対する `CommerceStore` など）も受け付けません。

`~/Developer/MyShop` はクイックスタートと同じようにアプリに追加できます（`import MyShop`、 `MyShopShell.main()`）。テストを実行してホストプロジェクトを開くこともできます。

```bash
cd ~/Developer/MyShop
xcodebuild test -scheme MyShop -destination 'platform=iOS Simulator,name=iPhone 17'

cd App
xcodegen generate
open MyShop.xcodeproj
```

`iPhone 17` は一例です。`xcrun simctl list devices available` に表示される任意のシミュレータを使えます。ホストプロジェクトには [XcodeGen](https://github.com/yonaskolb/XcodeGen) （`brew install xcodegen`）が必要です。

### テンプレートをその場で編集する

`Templates/<Name>/Package.swift` を Xcode で開けば、テンプレートを編集してテストを実行できます。 `Templates/<Name>/App` で `xcodegen generate` を実行してホストプロジェクトを生成することもできます。

### スキャフォールドライブラリを使う

テンプレートは `Templates/` から読み込まれるため、`TemplateScaffold` にはこのリポジトリのチェックアウトが必要です。

```swift
import Foundation
import TemplateScaffold

func makeShop(templates: URL, output: URL) throws -> ScaffoldResult {
    guard let template = TemplateCatalog.template(named: "ecommerce") else {
        throw CocoaError(.fileNoSuchFile)
    }
    let name = try ProjectName("MyShop")
    return try Scaffolder(templatesDirectory: templates).scaffold(template, as: name, in: output)
}
```

このコードはテストスイートでコンパイルされ、実行されます。

## アーキテクチャ

```text
Package.swift                 create-ios-app + TemplateScaffold (macOS)
Sources/CLI/                  argument parsing (swift-argument-parser)
Sources/TemplateScaffold/     catalog, name validation, renaming, copying
Tests/TemplateScaffoldTests/  Swift Testing, including a scaffold of every template
Templates/<Name>/             21 independent iOS 18 packages with tests and an App/ host
Examples/QuickStart/          an app project that runs a template as a local package
scripts/                      test-templates.sh, capture-screenshots.sh
```

各テンプレートの構成：

- `Sources/<Name>/`：公開の `<Name>Shell` アプリシーン、各画面、そしてサンプルデータと画面から呼ばれるすべてのアクション（カートの合計、注文や予約の状態遷移、承認キューなど）を持つ `@MainActor` の `ObservableObject` store。多くのテンプレートはこれを `<Name>.swift` にまとめていますが、 `EcommerceApp`、`FitnessApp`、`SocialMediaApp` は store、モデル、画面を別ファイルに分けています。
- `Tests/<Name>Tests/`：その store の Swift Testing スイート。派生値、状態遷移、不正な入力や未知の識別子に対する guard、超えてはならない上限を検証します。
- `App/`：XcodeGen の定義と、`<Name>Shell.main()` を呼ぶホストファイル。

`CleanArchitectureApp` は単一の store の代わりに 4 つのターゲットで構成されます。`CleanArchitectureAppDomain`（エンティティ、ルール、use case）、`CleanArchitectureAppData`（HTTP、JSON、キャッシュ、repository）、`CleanArchitectureAppPresentation`（`@Observable` モデルと画面）、そしてコンポジションルートである `CleanArchitectureApp` で、それぞれに専用のテストターゲットがあります。

テンプレートはルートパッケージにも互いにも依存しません。名前の変更はテンプレートのディレクトリ名のテキスト置換なので、変更が必要な名前はすべてその名前で始まります（`EcommerceApp`、 `EcommerceAppShell`、`EcommerceAppTests`）。

## ロードマップ

- パッケージを Swift Package Index に登録する。
- 残っている文字列ベースの状態を enum に置き換える。たとえば `EcommerceApp` の注文見出し、 `MessagingApp` の containment 状態、`AIAssistantApp` の preset モード。
- まだコードの大半を `<Name>.swift` に置いているテンプレートを、`EcommerceApp`、`FitnessApp`、 `SocialMediaApp` と同じように store、モデル、画面のファイルに分割する。
